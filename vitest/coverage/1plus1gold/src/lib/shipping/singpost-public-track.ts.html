/**
 * SingPost public-tracker status lookup — for EXTERNAL marketplace parcels.
 *
 * Lazada (and some other marketplace) parcels ship under the marketplace's
 * SingPost / Speedpost account, not ours, so the operator records only the bare
 * tracking number + the carrier label "SingPost". This lets the
 * `external-shipper-poll` cron converge their status the same way it already
 * does for SPX parcels (see spx-public-track.ts).
 *
 * The singpost.com track page calls an UNAUTHENTICATED JSON endpoint (verified
 * live 2026-10-20 with no reCAPTCHA token — the page runs one but does not send it):
 *
 *   POST https://www.singpost.com/api/services/track-events
 *        { "trackingNumber": "<tn>" }
 *   → { ok: true, items: [ { trackingNumberFound: "true", events: [
 *         { statusDescription: "Accepted at Drop-Off Point", aceStatusCode: "DP", date },
 *         { statusDescription: "SingPost has received your order information,
 *                               but not your item yet", aceStatusCode: "IR", date },
 *       ] } ] }
 *
 * An unknown number returns 200 with `trackingNumberFound: "false"` and no events.
 *
 * ⚠️ UNOFFICIAL endpoint (what the public page calls). Everything here is
 * FAIL-SOFT: any error, unexpected shape, not-found, or unrecognised milestone
 * returns ok:false so the order is left untouched. Never throws into the cron.
 * The response also carries recipient fields — they are never read or logged.
 */
