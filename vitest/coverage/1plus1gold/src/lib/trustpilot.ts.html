/**
 * Trustpilot's mark — the facts every surface that draws it must agree on.
 *
 * ▶ WHY A SHARED MODULE. These started inline in Footer.tsx when only the
 * footer carried the mark. It is now on four surfaces (web footer, web account
 * card, native Home band, native account card) and a second copy of somebody
 * else's TRADEMARK is worse drift than a second copy of a layout: a
 * half-updated one is a misuse of their mark, not just an inconsistency. The
 * footer's own history is three trust signals added to one breakpoint and not
 * the other for three months — a comment cannot enforce agreement, one
 * definition can.
 *
 * ▶ THE PATH IS CANONICAL, NOT DRAWN. Verbatim from `simple-icons`
 * (`icons/trustpilot.svg`), whose metadata cites Trustpilot's own style guide.
 * Same provenance class as the five Iconify payment marks in
 * PaymentMethodLogos.tsx, which the operator closed as accepted practice on
 * 2026-09-05 — with the caveat recorded there that each brand's own guidelines
 * still bind us. Never redraw it, and never substitute an SF Symbol or a
 * generic star: the glyph is a five-point star PLUS a detached lower-right
 * notch (the two subpaths), and an approximation of a trademark is worse than
 * an honest one.
 *
 * ▶ THE COLOUR IS A LITERAL, DELIBERATELY. It is Trustpilot's brand green, not
 * one of ours, so it must not move when our palette does. It is never a CSS
 * variable and never a colour token.
 *
 * ▶ WEB DRAWS THE PATH; NATIVE DRAWS THE RASTER. SwiftUI cannot decode inline
 * SVG (AsyncImage has no SVG support), so `scripts/export-review-marks.mjs`
 * rasterises this same path in this same colour to TRUSTPILOT_STAR_ASSET. A
 * test asserts the exporter and this file agree, so the two cannot drift.
 */
