/** A labelled footer group — one shared title style, centered content. Used for
 *  the bottom-band sections (Get the App / Accepted Payments / Follow Us /
 *  Reviews) so they all align and share the canonical footer title
 *  (cinzel xs gold-mid). */
function FooterGroup({ title, children }: { title: string; children: ReactNode }) {
  return (
    <div className="flex flex-col items-center gap-3">
      <p className="font-cinzel text-xs tracking-widest uppercase" style={{ color: "var(--color-gold-mid)" }}>
        {title}
      </p>
      {children}
    </div>
  );
}
 
/**
 * The bottom-band groups, defined ONCE and rendered by both the mobile and the
 * desktop band.
 *
 * ▶ This used to be two hand-kept lists with a comment on each asking the reader
 * to keep them in step, and that is precisely what failed: the header above
 * records three separate features (the D&B seal, accepted payments, the social
 * links) that were added to the desktop band alone and stayed invisible on
 * phones for three months. A comment cannot enforce agreement; one list can.
 * The two bands still differ in LAYOUT — stacked on mobile, a wrapping row on
 * desktop — so each wraps these in its own container, but neither chooses which
 * groups exist.
 */
function FooterGroups() {
  return (
    <>
      {/* App Store badge is self-gated inside StoreBadges on
          NEXT_PUBLIC_APP_STORE_URL. */}
      <FooterGroup title="Get the App"><StoreBadges /></FooterGroup>
      {/* Accepted payments — config-driven, mirrors checkout (same
          /api/payments/methods source). Title owned by FooterGroup. */}
      <FooterGroup title="Accepted Payments"><AcceptedPayments showLabel={false} align="center" /></FooterGroup>
      <FooterGroup title="Follow Us"><SocialLinks /></FooterGroup>
      <FooterGroup title="Reviews"><TrustpilotLink /></FooterGroup>
    </>
  );
}
 
/**
 * The footer's review link.
 *
 * ▶ It points at the PROFILE, not the write form. A footer is read by people who
 * have not bought anything — dropping a browsing stranger into a review form is
 * the pushiness we decided against, and the profile page carries Trustpilot's
 * own Write-a-review button for the customer who does want to leave one. The
 * direct ask lives where the person has actually bought: the parcel insert card
 * and the account block.
 *
 * ▶ NO star rating, score or widget. The account is new and carries no reviews;
 * a rating component with nothing in it reads as either broken or as a bad
 * score, and a fabricated one is not an option. Text until there is something
 * true to show — at which point Trustpilot's own widget is the honest upgrade,
 * because the number then comes from them rather than from us.
 *
 * ▶ It says it leaves the site, for the same reason the printed card does:
 * Trustpilot's value is that it is not ours, so implying otherwise would spend
 * the only thing an independent review is worth.
 */
/**
 * The Trustpilot logo, linked to our profile.
 *
 * ▶ A MARK, NOT A SENTENCE — the operator's call: *"I want the trustpilot logo
 * or widget here and not a statement in the footers."* A line of prose reads as
 * something we wrote; the logo reads as the platform, which is the point of
 * putting it in a footer.
 *
 * ▶ THIS IS TRUSTPILOT'S OWN FILE, BYTE-FOR-BYTE UNMODIFIED.
 * `public/images/trustpilot/logo-white.svg` is
 * `cdn.trustpilot.net/brand-assets/1.1.0/logo-white.svg` verbatim — md5
 * `8720c82b6b050d12486f63e0e8aaac1b`, verified against a fresh fetch of the
 * upstream, not against the copy. `logo-white-svg-is-upstream.test.ts` pins
 * that hash, so any edit — a recolour, an optimiser pass, a "tidy" — fails at
 * PR time. **Never hand-edit it.** Using a brand file exactly as provided is
 * the same posture the HitPay payment kit and the SME500 seal are held to.
 *
 * ▶ WHY `<img>` AND NOT INLINE SVG, deliberately, against the sibling idiom.
 * `SocialLinks` inlines its marks because lucide dropped the Instagram and
 * LinkedIn brand icons. Here the opposite applies: inlining means pasting path
 * data into a `.tsx`, where a future formatter or a careless edit silently
 * alters someone else's trademark and the hash guard can no longer see it. A
 * committed file is provably the file they published.
 *
 * ▶ SIZE. The lockup's viewBox is 1132.8 x 278.2, so the aspect is **4.0719**.
 * Drawn at width 110 the height is 27.0 — matching the 109x24 footprint the
 * previous composition occupied, so nothing in the footer moves. 110 is chosen
 * over a tighter 98 (height 24) to stay clear of the ~100px minimum that
 * Trustpilot's digital guidance sets for the horizontal lockup; their
 * guidelines PDF is not published on the CDN (403), so that floor is the
 * conservative reading rather than a cited number, and erring larger is the
 * cheap direction to err.
 *
 * ⚠️ REPLACED a star-plus-our-own-wordmark composition (2026-09-17, same day).
 * That used Trustpilot's canonical star path at the official `#00B67A` — real —
 * with "Trustpilot" set in OUR Montserrat, because every host serving the
 * official file was egress-blocked. The hosts were opened and this is the real
 * lockup. ▶ Worth knowing if anyone reconstructs it again: **their star is
 * TWO-TONE** (`#00b67a` over `#005128`), not the flat green a single-path icon
 * set gives you. One more reason not to rebuild a mark you can download.
 *
 * ▶ STILL NO SCORE, and still for the reason in `footer-trust-band.test.ts`: we
 * have no reviews yet, so a TrustBox showing a rating would show nothing or a
 * blank one. A logo makes no numeric claim, which is why it is honest at zero.
 * The genuine widget upgrade is Trustpilot's **Review Collector** TrustBox — the
 * one template built for a business with no reviews — which needs our Business
 * Unit ID. That is **gated on a paid Trustpilot plan** (operator, 2026-09-17),
 * so it is a commercial decision before it is an engineering one.
 *
 * ▶ It links the PROFILE, not the write form. A footer is read by people who
 * have not bought anything; the direct ask lives where someone has actually
 * bought — the parcel insert card and the account block.
 */
function TrustpilotLink() {
  return (
    <div className="flex flex-col items-center gap-1.5 text-center">
      <a
        href={BUSINESS_CONFIG.reviews.profile}
        target="_blank"
        rel="noopener noreferrer"
        className="inline-block transition-opacity hover:opacity-80"
      >
        {/* eslint-disable-next-line @next/next/no-img-element -- a static brand
            SVG: next/image would re-encode and proxy someone else's trademark
            through our optimiser for no gain, and an SVG has no raster sizes to
            pick. Explicit width/height reserve the box so nothing shifts. */}
        <img
          src="/images/trustpilot/logo-white.svg"
          alt="Trustpilot"
          width={110}
          height={27}
          loading="lazy"
          decoding="async"
        />
      </a>
      {/* Kept deliberately. The operator asked for the external hop to be
          disclosed wherever we send someone off-site ("that will open an
          external site, so we should say that") — a separate obligation from
          the mark, and secondary type, not the link itself. */}
      <span className="font-montserrat text-xs" style={{ color: "var(--color-muted)" }}>
        Independent review site — opens in a new tab
      </span>
    </div>
  );
}
