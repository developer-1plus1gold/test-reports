/**
 * POST /api/admin/orders/[id]/cancel-shipment
 * Header: x-admin-secret (admin-gated)
 *
 * Cancel a BOOKED courier shipment WITHOUT cancelling the order. The live
 * carrier booking is voided and the order returns to `shipper_status='pending'`
 * on the SAME carrier (unbooked) — so it drops back into that carrier's
 * "Awaiting" dispatch tile, where the operator can re-book it or switch it to
 * another carrier as a separate step.
 *
 * This is the standalone "Cancel booking" action (distinct from switch-shipper,
 * which cancels AND flips to Lalamove in one go). Primary use: a NinjaVan parcel
 * booked in error (e.g. a weekend order NinjaVan can't deliver) that we want to
 * un-book and then re-route.
 *
 * Deliberately does NOT touch the order lifecycle beyond the shipper axis:
 *  - Inventory is NOT released (the sale still stands — this only voids the
 *    courier booking, not the order). Inventory release belongs to order cancel.
 *  - Revenue is unaffected: lifecycle only reaches 'completed' at shipper_status
 *    'delivered'/'stored', and we hard-reject terminal states below, so a
 *    booked→pending move can never un-recognise revenue.
 *  - The stale tracking id is cleared atomically (optimistic guard on the old
 *    shipper_order_id) so a late carrier webhook can't clobber the reset order.
