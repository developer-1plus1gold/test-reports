/**
 * GET /api/admin/gold-yield/earnings
 * Per-participant summary: earned, owed, paid, pending.
 *
 * ▶ EARNED AND OWED ARE DIFFERENT NUMBERS, AND `pending` IS THE SECOND ONE
 * (2026-09-20). `participant_share` is what the bar EARNED them — their half of
 * the margin. The RETURNED PRINCIPAL is not earnings at all; it is their own
 * capital coming back. But we owe them both, and on a hedged bar the principal
 * is the larger by an order of magnitude.
 *
 * This route computed `pending` as earnings − paid, so it understated what we
 * owe by the whole principal — and that figure prefills the payout form's
 * amount, so an operator settling "in full" from it would have underpaid by
 * exactly that term. The exit gate has used `barOwedToParticipant` since it was
 * written; this route did not, so the same money had two answers depending on
 * which screen you were standing on. One helper now, three call sites.
 *
 * ▶ `total_owed_sgd`/`pending_sgd` are NULL, never 0, when they cannot be
 * computed. A sale row missing a principal makes the sum non-finite, and
 * showing that as zero would tell the operator nothing is owed on precisely
 * the rows where we cannot say. Same posture as the exit gate, which refuses
 * rather than guesses — and the payout form will not prefill from a null.
 *
 * ▶ BUT A NULL ALONE HID MONEY THAT IS PERFECTLY WELL KNOWN (2026-09-21). DEV's
 * one participant has ~50 sales predating the `principal_per_g` column, so
 * every figure on their row rendered "—" — including the S$121.22 of
 * participant share that is not in doubt at all. One unknowable input erased
 * the whole balance on the screen an operator pays from.
 *
 * So the row now carries `owed_computable_sgd` (a FLOOR — the rows we can
 * total) alongside `unknown_principal_sales`/`_grams` (why it is only a floor).
 * `total_owed_sgd` and `pending_sgd` stay null, so the payout form still
 * refuses to prefill and cannot quietly propose an underpayment; the operator
 * simply gets to see what is there and what is missing instead of a dash.
 *
 * ▶ IT ALSO CARRIES THE SPLIT AND THE OPEN REQUEST (2026-09-22). The operator
 * asked for the same detail the participant sees — "the admin should have
 * similar details" — and the two are not cosmetic: profit is money we owe on a
 * trade, principal is the participant's own capital coming back, and an
 * operator settling a balance should know which they are sending. The open
 * request is what the participant's button reads, so the screen that closes it
 * has to be able to see it.
 */
