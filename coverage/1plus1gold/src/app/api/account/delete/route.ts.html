 * POST /api/account/delete
 *
 * Account deletion — required by Apple guideline 5.1.1(v) and PDPA.
 *
 * Flow:
 *  1. Verify caller is authenticated (Supabase session cookie).
 *  2. Verify the confirmation phrase ("DELETE MY ACCOUNT") in the body.
 *  3. Cancel any pending/unpaid orders (status='pending'/'unpaid').
 *  4. Anonymise the customer row (display_name, tree_theme cleared).
 *  5. Anonymise the auth.users row (email + phone → uniquely tagged
 *     deleted-tombstone so the same person can't sign in to the old
 *     account; FK references in orders/payments/etc. survive intact).
 *  5b. Remove the remaining sign-in methods — passkeys (webauthn_credentials)
 *     and federated identities (auth.identities: Apple/Google/email/phone) —
 *     so NO method (not just phone/email) can resolve back to this row.
 *  6. Sign the user out (cookies cleared by the client after this returns).
 *
 * What is NOT deleted: past orders, payments, audit trails, gold tree
 * branches' aggregate amounts. These are kept for legal/accounting
 * (Singapore IRAS 5-year record-keeping requirement) but are
 * disassociated from any identifying PII.
 *
 * This is intentionally a one-way operation. There is no undelete.
 */
