/**
 * GET /api/cron/vault-audit-reminder
 *
 * Monthly operational reminder for the vault custody audit promise. The v1.1
 * custody agreement commits us to a month-end reconciliation of every
 * customer's in-custody holdings (plus on-demand audits). This cron makes sure
 * that promise is actually kept: on the 1st of each month it finds every
 * customer holding gold in custody who has NOT had an audit logged in the month
 * just ended, files a Control Tower `notify` item, and WhatsApps the admin team.
 * Admin then signs each audit via Admin → Vault → "New audit".
 *
 * Admin-reminder only (Mukesh's call 2026-06-27). Customer-facing "your
 * statement is ready" notification is Phase-2 post-launch.
 *
 * Reuses existing infra: vault_holdings (IN_CUSTODY_STATUSES) + vault_audits +
 * agent_decisions (Control Tower) + sendAdminAlert. Scheduled `0 2 1 * *`
 * (02:00 UTC on the 1st — day-of-month crons fire reliably, unlike the
 * day-of-week one that silently stalled; see planner-heartbeat).
 */
