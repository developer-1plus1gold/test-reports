/**
 * POST|GET /api/cron/singpost-status-poll — every 15 minutes (2026-11-21).
 *
 * SingPost has no webhooks, so this is the only way a SingPost parcel's status
 * reaches us — the same spine spx-status-poll is for SPX. It asks SingPost's
 * authenticated Tracking API (unforgeable, so its answer is safe to apply for
 * every status including delivered) about every live SingPost order, in batches.
 *
 *   - Forward only: an order moves only when SingPost's furthest event ranks
 *     above its current status (lib/singpost/status.ts). The status RPC also
 *     refuses to touch a delivered / failed order.
 *   - Delivered: bars sold + the customer's delivery WhatsApp, once, through the
 *     shared onCourierDelivered (only when the RPC actually changed the row).
 *   - A failed delivery attempt does not change the status (SingPost retries);
 *     it is written to shipper_error so the Dispatch tile shows it, and cleared
 *     when a later event supersedes it.
 *
 * A no-op that says so until the tracking key is set, and while there is no
 * live SingPost order (always, until the first booking). It does NOT stop for
 * the Admin → Shippers switch once parcels are out: turning SingPost off stops
 * new bookings, but a parcel already with SingPost must still reach delivered,
 * or its bars are never marked sold.
 *
 * Covers: shipper 'singpost' with a tracking number, not delivered / failed, not
 * cancelled / refunded, booked in the last 14 days (next-day service, 2
 * re-attempts, then a return).
 */
