/**
 * GET /api/cron/hitpay-reconcile
 *
 * The safety net for MISSED HitPay webhooks. Runs frequently (every 10 min).
 *
 * The webhook + client polling are the only completion paths, and both miss:
 * a webhook can fail to arrive, and PayNow customers routinely pay in their
 * banking app and never return to the site (so the client never polls). This
 * cron asks HitPay directly for every still-pending order and completes the
 * ones that were actually paid — so "customer didn't come back" auto-recovers
 * within ~10 min instead of being lost.
 *
 * Window: rows aged 3 min – 48 h. The 3-min floor gives the webhook / live poll
 * first crack (avoids racing them); the 48 h ceiling bounds HitPay API calls
 * (older unpaid rows are terminal and get expired by hitpay-pending-cleanup).
 *
 * PROD-only (DEV has no scheduler). Protected by CRON_SECRET.
 *
 * NOTE: conversions (hitpay_pending_conversions) share the same missed-webhook
 * risk and need the same treatment — tracked as a fast-follow.
 */
