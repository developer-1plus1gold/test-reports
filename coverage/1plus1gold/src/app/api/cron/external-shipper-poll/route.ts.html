/**
 * GET/POST /api/cron/external-shipper-poll
 *
 * Runs every 30 minutes via Vercel Cron.
 *
 * Auto-updates the delivery status of EXTERNAL marketplace orders (Shopee etc.)
 * that are in dispatch. These parcels are shipped under the marketplace's own SPX
 * account — NOT ours — so our SPX Open Platform `trackOrder()` (used by
 * `spx-status-poll` for our own bookings) can't see them. Until now the operator
 * updated them by hand via the "Track" button (which only opens the public tracker
 * page, never writing status back), so a delivered Shopee order sat stale in the
 * Dispatch tab until someone noticed.
 *
 * This polls SPX's public tracker JSON for each in-flight external SPX parcel and
 * converges its `shipper_status`, mirroring `spx-status-poll`. On DELIVERED it
 * mirrors the manual "Delivered" action EXACTLY — `shipper_status='delivered'` +
 * `status='completed'` + `pod_at` (which realises the sale's revenue/COGS) — so
 * the order completes and drops out of the Dispatch tab (whose external bucket
 * filters `shipper_status NOT IN ('delivered','failed')`) with no hand-tap.
 *
 * Design choices:
 *  - FORWARD-ONLY: only advances a status (rank guard), never regresses.
 *  - CONSERVATIVE on failures: it never auto-sets `failed`. A delivery exception
 *    is left for the operator (who still has the Track button) rather than
 *    silently pulling the order off Dispatch as if resolved.
 *  - FAIL-SOFT: the public endpoint is unofficial; any error on one order is
 *    logged and skipped, never breaks the batch. No customer WhatsApp is sent
 *    (the manual `deliver` action doesn't either — the buyer's contact is the
 *    marketplace's, not ours).
 *
 * Vercel Cron invokes with GET (a POST-only handler would 405 every tick and
 * never run — root-caused 2026-07-30), so GET is aliased to POST. Protected by
 * CRON_SECRET.
 */
