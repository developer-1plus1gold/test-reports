/**
 * POST /api/admin/lamination
 *
 * Records one lamination event in a parent-first session: operator has
 * already picked a split-parent inventory row to break down (50g/100g Combibar
 * or PAMP Multigram+25, via /api/admin/lamination/parents), and now scans one
 * (NFC card, RFID box) pair per physical 1g split as they laminate.
 *
 * Each call:
 *   1. Verifies the picked parent inventory row is still eligible
 *      (status in available/broken_down, capacity remaining).
 *   2. Verifies NFC card (unassigned, product = 1g split) and RFID box
 *      (active, not currently filled).
 *   3. Creates ONE child inventory row:
 *        source_type = 'breakdown'
 *        product_id  = the 1g split product
 *        parent_inventory_id = picked parent
 *        cost_per_g_sgd inherits from parent
 *        nfc_serial + rfid_tag set, status = 'available'
 *   4. Marks parent status = 'broken_down' on the FIRST child created
 *      against that parent (subsequent calls leave it).
 *   5. Stamps nfc_serials.parent_bar_serial with the parent's serial_number
 *      so /verify can render it.
 *
 * Capacity is enforced server-side: a parent caps at its gram weight in
 * children (25g Multigram → 25, 50g → 50, 100g → 100). The parent's remaining
 * capacity is returned in the response so the UI can update its "X / N" counter.
 */
